Keyset conditions in CursorPageRepositoryImpl.addPositionQuery

How the next page is selected from the values of the last record of the current page, including null values.

For the positions A, B, ID the condition for the next page has one OR-term per position:

   (A-term)
OR (A = :a AND B-term)
OR (A = :a AND B = :b AND ID-term)

If a cursor value is null, the tie condition is IS NULL instead of = :value. Null values follow the database ordering (PostgreSQL): ASC puts nulls last, DESC puts nulls first. A reversed request flips the order and with it the null placement, so the same rules apply.

The code and its branches

for ( final var position : request.positions() ) {
    final var attribute = position.attribute();
    if ( position.hasValue() ) {
        cqb.orWhere( and( valueConditions, switch ( position.order() ) {
            // 1 value, ASC: bigger values follow, and nulls (last) too
            case ASC -> cqb.cb()
                    .or( cqb.greaterThan( attribute, position.value() ),
                            cqb.isNull( attribute ) );
            // 2 value, DESC: smaller values follow, nulls (first) are already done
            case DESC -> cqb.lessThan( attribute, position.value() );
        } ) );
        valueConditions.add( cqb.equalTo( attribute, position.value() ) );
    } else {
        if ( position.order() == Order.DESC ) {
            // 3 null, DESC: nulls are first, every value follows
            cqb.orWhere( and( valueConditions, cqb.cb()
                    .not( cqb.isNull( attribute ) ) ) );
        }
        // 4 null, ASC: nulls are last, nothing follows - no OR-term, only the tie condition
        valueConditions.add( cqb.isNull( attribute ) );
    }
}

Example 1.2: reversing Example 1

To go back from a page, its request is reversed with PageRequest.toReversed(). Every position flips its order, so sortBy(A:desc, B:desc, ID:desc) becomes A:asc, B:asc, ID:asc, and the nulls move from first to last. The cursor becomes the first record of the current page (the nextValue stored with the position), so the query returns the records before it. The content of a reversed page is reversed again, so it is shown in the original order.

Going back from page 4 of Example 1 (IDs 1, 4) uses the reversed request of page 4 with the cursor ID 1 = (A=9, B=1). In the table, the records are listed in query order; bold rows are the last record of a query result and become the cursor for the next step back.
